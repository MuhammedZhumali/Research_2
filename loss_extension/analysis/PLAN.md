# Analysis specification for the frame-loss extension

The primary population is the simulated persistent-stuck-ON population. Three observation profiles have equal weight. Within each profile average the per-episode fractions of true failed OFF transitions receiving a correct fault report within six hours of the command. Each faulty episode counts once, whether it contains one or two failed transitions. Also report raw detected and total transitions for orientation. Their pooled ratio is a different estimand. All policies share each episode, schedule, and allocation.

Primary comparisons use the calculated KazSTSAT schedule and the 32 bit/s stream allocation. There are six two-sided contrasts: all three method pairs under random erasure and under selective erasure. Compute the within-episode difference before averaging within profile. Resample complete paired faulty episodes, separately within each profile, then combine with equal profile weights. Use 20,000 nonparametric bootstrap draws with NumPy PCG64 seed 8317402. Report percentile endpoints at 0.05/12 and 1-0.05/12 for the six-comparison family (Bonferroni adjustment; approximate, not a finite-sample guarantee). Preserve common bootstrap draws across conditions. A positive interval favors the first-named policy. A policy leads in an arm if both adjusted pairwise intervals favor it. Otherwise identify the observed leader/tie and describe what remains unresolved. Zero sample variability may collapse a bootstrap interval. This is not proof of zero population variability or equivalence.

Secondary results use pointwise 95% descriptive episode-bootstrap intervals for timely fault detection and its paired differences in other conditions. Profile-level results, outcomes and costs are descriptive. Other endpoints include any incorrect nominal report on a true failed transition by the six-hour deadline, absence of a definitive report, unresolved fault by the deadline, and delay capped at six hours. A transition may receive both an incorrect and a correct report. No definitive report is a subset of unresolved transitions. Wrong reports are retained even when corrected. Separately report the proportion of wholly healthy episodes receiving any false alarm. Class assignment is balanced for sensitivity testing and is not an estimate of on-orbit fault prevalence.

Wire bytes are actual data and acknowledgments attempted in the full 24 h episode. Report both occupied airtime and total reserved transmission time (including reserved but unused ACK slots); no credit for an erased frame and no uncharged retries. Account for prefix traffic from episode start and report contacts to diagnosis only on resolved true fault transitions along with eligible counts. Prefixes overlap. Do not add transition prefixes or compare their conditional averages as unconditional efficiency. Where the same true fault is eventually detected under both an impaired arm and clean delivery, also report paired extra detection time and contacts. Signed differences can be negative under a changed selection history. Always display the number of clean detections lost to the deadline.

Clean/random/selective, schedules and rates reuse the same episodes. Inference never counts repeat evaluations as independent. Check all possible run cells, episode identifiers, target truth/timing across methods, delay arithmetic (including unresolved), budget and ledger identities. Original frozen experiments remain separate. Simulated erasures establish results only for the specified frame availability model.
